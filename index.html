01

一切从香农开始

信息，是消除了多少不确定性

Ronin 说香农「到处都有他」。这不是客气话。你今天用的每一个大模型，训练时盯着的那个分数，都是香农 1948 年那篇论文的后代。

香农与信息论

一句话一条消息越出乎意料，带的信息越多。信息的单位叫 bit。

展开在沙漠里听到「明天晴」，你几乎什么都没学到，本来就是晴。听到「明天下雪」，你吓一跳，这条消息信息量很大。

1948 年，香农在《通信的数学理论》里把这个直觉变成了公式。他故意不管「意义」，只算「意外」。由此他定义了熵（平均有多意外），算出一条线路每秒最多能可靠地传多少 bit，也证明了压缩和纠错的极限。今天所有数字通信、压缩包、纠错码都建在这上面。

和大模型语言模型训练时有一个分数叫交叉熵，说人话就是「猜下一个词猜错了多少」。它是香农熵的直系后代。AI 圈有一条核心信念：猜得准 = 压得小 = 看懂了结构。源头就是香农。

跟你的关系你做 GEO 时看到的 perplexity（困惑度）就是熵换了个写法（2 的熵次方）。数字越小，说明模型读这段文字越「不意外」。

来源：Shannon (1948). A Mathematical Theory of Communication. Bell System Technical Journal.

「信息」有四张脸

一句话同一个词「信息」，在科学里至少有四种互不相同的意思。混着用，就会说错话。

展开他发给你的那篇 Nature Reviews Physics 文章（Rosas、Mediano、Carroll，2026 年 8 月）列了四张脸：

  • 工程的：香农那种，一根线能传多少。
  • 统计的：知道 A，能让你对 B 少猜多少。比如知道今天阴天，你对「会不会下雨」就少猜一点。
  • 热力学的：信息是实打实的物理量，擦掉一个 bit 要花能量（Landauer 1961）。
  • 本体论的：物理学家惠勒的说法，世界本身就是由信息构成的（it from bit）。

文章不打算选出一个正确答案。四种都对，各管各的地盘。正文有付费墙，每张脸的解释按术语通常含义给出

为什么发给你他自己说：「澄清了一个符号背后的若干表征。」「信息」是一个符号，背后有四种东西。大模型也是一个符号系统，它学到的是第二张脸：词和词之间谁常跟着谁。它学到的不是意义本身。这就是他那句「因为 LLM 是语言模型」的意思。

来源：Rosas, Mediano & Carroll (2026). Four faces of information in natural systems. Nature Reviews Physics.

香农有自己的目标函数

一句话你搜到香农爱吹单簧管、带妻子去赌场，Ronin 说：「他有自己的目标函数。」

展开「目标函数」是机器学习的词：训练时模型拼命去优化的那一个分数，它的一切行为都朝那里长。说一个人有自己的目标函数，是说他真正在追的东西，不是别人以为的名和利。

传记《A Mind at Play》里香农的样子：

  • 1950 年做了一只机械老鼠「忒修斯」，会在迷宫里试错、记住路线，是最早的机器学习装置之一。
  • 和数学家 Thorp 做了一台藏在身上的小电脑预测轮盘赌：脚趾按开关，耳机听结果。1961 年两对夫妻去拉斯维加斯实测。下注的思路叫凯利公式，是他的同事用信息论推出来的：你掌握的信息优势有多大，就押多少。
  • 杂耍、骑独轮车，还做了一台唯一功能是「把自己关掉」的机器。

你问 Claude 的名字是不是致敬他，Ronin 说答对了。据媒体转引纽约时报，未见 Anthropic 官方说法

跟你的关系一个人优化什么，决定他长期能做成什么。这个问题第 11 章还会回来。

来源：Soni & Goodman (2017). A Mind at Play；作者 2017 年 Reddit AMA；Bridge Michigan 报道。

信息时代七人组

一句话他说你「会在不经意间遇到他们」。七个人分两派：一派定义了机器，一派研究人和机器怎么配合。

定义机器的

  • 图灵：1936 年证明有一台「万能机器」，能扮演任何别的计算机器。他划出了「什么能被算」的边界。图灵测试也是他提的。
  • 冯·诺依曼：1945 年定下「程序和数据放在同一个抽屉里」，今天所有电脑都长这样。
  • 香农：就是上面那位。

研究人机配合的

  • 维纳：1948 年《控制论》。核心是反馈回路：做一下、看结果、和目标比、再调。今天 agent「执行、观察、修正」那一圈就是它。
  • 司马贺：人不找最好的答案，找够用的答案。1971 年他写下「信息的丰富造成注意力的贫乏」，「注意力经济」从这里来。
  • 恩格尔巴特：1962 年主张计算机是用来增强人，不是替代人。1968 年第一次公开演示鼠标和超链接。
  • 艾伦·凯：面向对象编程的原始提出者。他的原意是把程序拆成一群互相发消息、各管各的小细胞。Java 课本里那套层层继承，是后人加的。

跟你的关系Ronin 明显偏后一派，你的 Gallup 结构（读人、读技术、自己能交付）也在后一派。你在 DLG 做的 AI adoption，职业上的祖师爷是恩格尔巴特。当年 Java 课上让你死去活来的 OOP，凯本人的版本其实简单得多。

02

它每次都不记得你

模型是一张白纸，记忆都在纸外面

这是「先学这五个」里的第一个。它直接决定你每天怎么用 Claude Code：为什么窗口会满，为什么要写 CLAUDE.md，什么时候该重开。

模型是无状态的

一句话每次调用模型，它都是一张白纸，不记得上一次。所谓「记忆」，是你这一次把前情重新递给它。

展开想象一位极聪明的实习生，每天早上醒来都忘了昨天。聊天窗口看起来连贯，是因为每说一句，软件都把整段聊天记录从头递给他一遍。

所以「上下文窗口快满了」不是模型累了，是递过去的那一沓纸太厚了。CLAUDE.md、memory 文件、项目索引，全都是同一种东西：把状态放在模型外面，替它记事。

跟你的关系你现在的习惯是：窗口满了就开新窗口，口头重讲一遍，让它重新扫一遍代码。每一次，都在为「它不记得」付全价。

这是你 09-13 记下的三个主题之一。

模型也是一台计算机

一句话你说「模型也是计算机」，他接了一句「Karpathy 说的 Software 3.0」。

展开写程序的方式换了三次：1.0 是人一行行写代码；2.0 是训练出来的神经网络；3.0 是用大白话写的 prompt，大模型就是执行它的那台电脑。

Karpathy 2025 年 6 月的演讲里有个比方：模型是 CPU，上下文窗口是内存，prompt 是程序。现在就像 1960 年代：电脑贵，放在机房，大家排队分时间用。

演讲里和你最相关的一段：好用的 AI 产品都给你一个「自主度滑杆」，AI 先做，人来验，产品的本事在于让「做一验一」这一圈转得快。第 5 章会接着讲。

跟你的关系把它当电脑看就好懂了：一台每次开机都清空内存的电脑。CLAUDE.md 和 memory 文件，是它的硬盘。

来源：Karpathy, Software Is Changing (Again)，YC AI Startup School，2025-06；对话 09-15。

上下文税

一句话每开一个新会话就让它重读整个项目，是在一遍遍交税。办法不是不做索引，是把索引做成能读、能维护的样子。

展开你说试过让 Claude 把项目整理成一份 Markdown 索引，不满意：人读着累，重点也抓歪了。Ronin 的回答很短：那是索引写得不可维护，不是索引没用，「那就设置规则」。

规则可以是一张固定的表，让它填空，而不是自由发挥。比如六栏，每栏最多三行：

  1. 这个项目要解决什么
  2. 入口文件在哪
  3. 数据怎么流
  4. 已经拍板的决定
  5. 还没决定的事
  6. 最近三次改了什么

跟你的关系你已经有一个 /handoff 命令在做类似的事。差的两步：把它变成固定模板；在每次会话结束时自动跑（用 hook）。下一个会话读的就是一页纸，不是整个代码库。

codegraph：给代码画一张地图

一句话他问你：「那你为什么不装一个 codegraph？」它把代码库预先画成一张地图，agent 查地图，不用一条街一条街走。

展开常被提到的是 GitHub 上的 maxmilian/codegraph：把代码拆成「谁定义了什么、谁调用了谁」的关系，存进本地数据库，再通过 MCP 交给 Claude Code。文件一保存就自动更新。它是按语法规则拆的，不是让大模型总结，所以不会「抓错重点」。

作者自报：工具调用少 88%，token 少 62%。厂商自测数字，你的仓库要自己量

跟你的关系你觉得「让 cc 读一遍代码最直观」。读地图比读代码便宜得多，也不靠某一次总结的质量。可以先在 joran-LiveTranslate 或 coco 上试一个。

fan-out，和散会后的白板

一句话你截图里那套「一个主 agent 派活给一群子 agent」叫 fan-out。它解决一次会话里的并行，解决不了「散会以后还记得」。

展开像一场会里分了五个小组讨论，每组写满一块白板。散会时白板全擦掉。他问的正是这个：「你这里就是一个 fanout 模式，但是跨 session 乃至跨 project 呢？」

想让东西活过一次会话，只有三条路：写进文件（索引、memory、CLAUDE.md）；写进地图（codegraph）；或者等第 3 章说的「一直开着的机器」。

skill 该放哪：先弄清什么叫「项目」

一句话项目是有终点的事。「我怎么读书」「我怎么写文案」不是项目，是管着所有项目的习惯。

展开他说把 skill 绑在项目里能减少「skill 爆炸」。你举了反例：微信读书 skill 没法放进某个项目。他补了一个定义：项目是「为了一个独特成果而做的临时性工作」，有头有尾。「读一本书并画出来」是项目；「我怎么读书」是更高一层的东西，天然属于全局。

一个好用的分法：

  • 有终点、只服务这一个仓库的 → 放项目里的 .claude/
  • 跨项目反复用的能力 → 放全局 ~/.claude
  • 连能力都不算，只是你的偏好和背景 → 放 memory

他顺手说的两句「划线等于你的偏好权重标注」：你划的每一道线，都是在告诉自己「这个重要」，和给模型做偏好标注是一回事。「被转移的那部分已经被编码了」：你截图、存进笔记的那个动作，本身就是在记，所以不划线也没丢。

上下文脏了，就重开

一句话一个错的前提一旦写进上下文，后面每一步都会被带偏，而且退不回去。最省事的办法是开新会话。

展开像一滴墨滴进一杯水，你没法把它挑出来。钱鹏飞在 9.9 那场会上说：「注入了错误的上下文……它不会把它回滚掉，这东西一直会在。」Ronin 的解法：「你不如直接重新开一个 session。」

这里要分清两种情况：

  • 窗口满了：该做的是把状态放到外面（索引、memory、handoff），别让它重读。
  • 窗口脏了：早先一个错的假设已经在里面。这时重开是对的，不是浪费。重开时只带「已经确认的结论」，不带过程。

跟你的关系判断信号很简单：你发现自己在第三次纠正同一个误解，这个会话就脏了。

「叫我哥」：一只金丝雀

一句话他让 agent 每次都叫他「哥」。哪天它不叫了，他就知道上下文已经炸了，前面的规矩它跟不住了。

展开以前矿工下井会带一只金丝雀，它先倒下，人就知道空气有毒。「叫哥」这条指令本身没用，但它和你真正在乎的规矩（格式、语气、不许做的事）写在同一个地方。它先掉，说明那些也快掉了。

为什么会掉：对话越长，模型对开头那些话越不上心。2023 年一篇叫「Lost in the Middle」的研究发现，长长一段上下文里，中间的信息最容易被忽略。

现成的类比：摇滚乐队 Van Halen 的巡演合同里有一条「后台不许有棕色 M&M 豆」。主唱后来解释，他们的舞台设备很重，合同里有一堆安全条款；碗里只要出现棕色豆子，就说明主办方没细读合同，所有安全项都得重查。

跟你的关系你现在是「窗口快满了就停」，看的是容量。金丝雀看的是质量：窗口没满，规矩也可能已经掉了。今天就能在一个项目的 CLAUDE.md 里试：让它固定用某个词开头，看大概聊多长它开始漏。

来源：对话 09-27；Liu et al. (2023). Lost in the Middle；David Lee Roth (1997). Crazy from the Heat。

砌墙还是建教堂

一句话他这阵子反复说：模型已经差不多了，拉开差距的是模型外面那一整套工程。Claude 的那一套「设计得非常美」。

展开同一位厨师，给他一间设备齐全、刀具摆好、菜谱贴墙的厨房，和给他一口锅，做出来的菜不是一个水平。模型就是那位厨师，外面那套工程（工具、规则、上下文的组织）就是厨房。业内叫它 harness。

他的原话：「模型已经达到均线了，但是各家的 harness 惨不忍睹。」「Anthropic 非常耐心地给 Claude 这个模型准备好了它的工作台。」「LLM 只能吐 token，决定最终渲染效果的是一套复杂工程。」他说自己已经部分复现了「用 GPT 做出 Claude 的输出质量」，感觉是 GPT 的工程拖累了它的模型。还说「光是交互，Claude 就做了 39 个」。39 这个数是他看到的，未核实

「你是在砌墙还是在建造教堂」，是他转来和博庸聊天时的一句。

跟你的关系你在 DLG 教同事用 AI，最常听到「它答得不好」。更准的诊断是：多数时候不是模型不行，是没给它工作台（文件、工具、规则、上下文）。你自己的 skill、MCP、CLAUDE.md，就是在搭工作台。

三个石匠

延伸 · 出处原笔记说「砌墙还是建教堂」出自一个流传很广的寓言，出处不可考。补一点：这个寓言最常被归到管理学家德鲁克 1954 年的《管理的实践》。有人问三个石匠在干什么，第一个说「在挣钱糊口」，第二个说「在做全国最好的石匠活」，第三个说「在建一座大教堂」。

有意思的是，据转述，德鲁克担心的恰恰是第二个：只顾把自己的手艺做到极致，忘了整座建筑要什么。放回 Ronin 的话里：把单个模型调到最强是第二个石匠，把工作台搭好、让模型为整件事服务，才是第三个。

延伸来源：Drucker (1954). The Practice of Management（多见于二手引述，原书页码与更早出处未核实）；HR Exchange Network: Drucker on the Danger of Professionalism。

03

状态的三次搬家

思考到一半的东西，放在哪里

这是他那篇署名文章《基础模式：第三次更替》的骨架。过去四年模型的每次换代，表面上眼花缭乱，其实只动了一个变量。

四次搬家

一句话模型每次换形态，动的都是同一件事：「想到一半的东西」放在哪。

展开拿做一道难题来比：

  • 第一次，写在草稿纸上。模型把想法一个字一个字写出来（叫「思维链」，CoT）。好处是不用在脑子里硬记；坏处是写下就擦不掉，第三步的「有可能」到第十步就变成了「就是」。
  • 第二次，草稿纸加出门查资料。模型可以调工具、看结果、再决定下一步（叫 ReAct，也就是今天的 agent）。Cursor、Claude Code、Codex 都长在这一格。
  • 第三次，收回脑子里。同一个脑子把问题闭着眼过好几遍，不说话，想完才开口。每过一遍都能推翻上一遍。这是第一次有了「回头路」。他称为「第三个基础模式」。
  • 第四次（他的赌注）：一台一直开着的机器。状态从不清零。

他举的例子：问投资人「26 年还值得买苹果吗」，脱口而出是「不如买英伟达」；闭眼多想几遍，会改口。用的是同一个脑子，只是多转了几圈。

第三次搬家，哪些是真的

一句话「模型在脑子里绕圈」这条研究路线是真的；「GPT-6 Astra 用了它」是他的推断。

展开研究里叫 latent reasoning 或 recurrent depth。代表作：Meta 2024 年底的 Coconut（让模型在内部推理，不把每一步写成字），和 2025 年初的 Huginn（同一块网络循环任意次，用圈数换深度）。

Ronin 自己在文档里分得很清：「这条路线存在」是观察，「Astra 用了它」是推断，「没有人在外面能证实」。推断你读的时候也分开。

Astra 博客说了什么这部分核实过。OpenAI 开发者博客讲怎么给 GPT-6 Astra 写 skill 和 prompt：

  • skill 的描述越短越好，只说清「什么时候用」。skill 本身变成一个「指路牌」，指向该读的文档。
  • 「过于具体的指导，现在可能反而拖累结果。」
  • AGENTS.md 别再写「每次改代码前先读全部文档」，改成按场景给链接。
  • 模型对「什么时候该停」更犹豫了，所以完成标准要你事先写清。

跟你的关系这直接反驳了你「与其设计索引，不如口头重讲一遍」的习惯。方向变了：给 agent 的不是更多说明，是更短、更准的指路牌。你的 CLAUDE.md 和 skills 可以按这个标准做一次减法。

来源：OpenAI 开发者博客 Rethinking skills and prompts for GPT-6 Astra；Hao et al. (2024) Coconut；Geiping et al. (2025) Huginn。

同一盏灯

一圈循环，最慢的总是人

他这一个多月讲得最多的一个词是 loop：做一下、看结果、再改。AI 那一段越跑越快，整圈的速度就越来越取决于另一段：你审得过来吗？

loop 的四格，和「限制在人」

一句话他发过一张四格图：一圈循环由什么组成、每一段交给谁、为什么要循环、以及人机循环的限制在人。

展开原图当时没读到，按他说过的话推测每一格：推断

  • 组成：看、想、做、看结果、修正。就是维纳那个反馈回路。
  • 分配：哪一段交给大模型，哪一段交给小模型或工具，哪一段留给人。
  • 为什么要循环：他说过「用循环的次数换窗口的长度」。一次想不清的事，拆成好几圈，每圈只带必要的东西。
  • 限制在人：这一格对得上一条老定律。

阿姆达尔定律一件事里不能加速的那一段，决定了整件事最多能快多少。比如人工那一段占整圈时间的 20%，AI 那部分就算快到零，整圈最多也只能快 5 倍。

跟你的关系你一个人干六个人的活。瓶颈多半不在 agent 跑得慢，在你审产出、给反馈这一步。两个提速办法：事先把验收标准写清，让 agent 自己先查一遍；让产出变成一眼能审的样子（对比表、改动高亮），少读长文。

火锅店的收银台

延伸 · 比喻与公式一家火锅店，后厨从 2 个厨师加到 20 个，上菜快多了。但收银台只有一个，结账的队排在门口，翻台率还是上不去。加再多厨师，也快不过收银台那一步。

写成公式：如果不能并行的那一段占比是 s，并行的那段分给 N 个人，整体最多快 1 ÷ (s + (1−s) ÷ N) 倍。N 再大，也顶不过 1 ÷ s。你的「收银台」就是你自己审稿的那一步。

延伸来源：Think Insights: Amdahl's Law；Amdahl (1967). AFIPS Conference Proceedings。火锅店比喻为本页自拟。

探照灯与事件线

一句话Chat、Co-pilot、Agent 是同一盏灯，区别只有一个：你手里的线有多长。

  • Chat：只扫到想法，给你方案，路你自己走。尺度是秒到分钟。
  • Co-pilot：扫到你工作里的几个节点，替你做几段，你随时喊停。尺度是小时到天。
  • Agent：扫到更大的业务，你只握两端：给目标、做验收。尺度是周到月。

当晚他把它做成了 60 秒的视频《同一盏灯》，论证是这样走的：

  1. 直觉以为 Agent 是「更大的圆」，其实是「更低的灯」。离世界越近，光越窄、越硬。
  2. 只有碰到世界才有回波。峰是人在想，谷是 AI 在做，触地的地方弹回一个绿色方块。
  3. 世界越会反光，线才能放得越长。测试、编译器是镜面，回波又多又清楚，可以放心交出去；战略、品味是黑绒布，光被吞掉，没有回波。

机器人在真实世界里跑 loop

一句话一家机器人公司让机器人在现场试错，只用约 15 分钟的真实数据，就把拧螺丝、插网线这种毫米级动作练熟了。

展开Physical Intelligence 的 RLT。背景是：大的机器人模型什么都会一点，但最后一毫米不准；拿整个大模型现场练又太慢太贵。他们的办法像「师傅带徒弟」：大模型给方向，一个很小的网络在现场一圈圈地微调，只管修正最后那一点。

结果：电动螺丝刀拧小螺丝，从每 10 分钟约 5 次提到约 15 次。算上复位，总共练了约两小时。插网线那个任务，最后有一半的尝试比任何一次人类遥控都快。

为什么在这一章这是 loop 放进了物理世界。螺丝拧歪了就是歪了，这种「回波」只能在真实世界里拿到，也就是上一章说的「逃不掉的边界」。

工具箱：爬行类和哺乳类

CLI / MCP / Web / App

一句话你把 connector 拆成 CLI 和 MCP 两类，被人喷「太技术了」。他花四十分钟拆成四格，最后给了一句最好记的：CLI 是爬行类，MCP 是哺乳类。

用一家餐厅来比

  • CLI（命令行）：你自己进厨房，照着菜谱做。东西在你本地算。他的例子：「你说给我做饭，然后程序就给你做饭。」
  • MCP：餐厅给服务员一本带说明的菜单：有哪些菜、每道怎么点。agent 看了说 ok，一句「老样子」就能上菜。它是一种协议，计算放在服务器那头，所以能控制隐私和安全。
  • Web（网页）：你打开别人的一份文档，其实是把整份内容搬到你电脑上，再在你这儿显示出来。他说：「网页对于你而言是一个裸体，因为你已经拿到了数据。」
  • App：菜在后厨做，你只看到端上来的成品。

你的总结是「app = MCP，web = CLI」。他的总结是爬行类和哺乳类：CLI 更底层、管执行；MCP 带着意思，适合 agent。「你可以直接比划来点餐，也能一句『老样子』让 agent 给你上菜。」

他还补了一句：connector 一般在远端（比如 Notion 的服务器），本地的是 CLI 那一格。

跟你的关系你拆成 CLI/MCP，方向没错，缺的是中间两格。你给同事那句「传统软件能不能被 agent 用，就看它有没有开放 CLI 和 MCP」仍然成立，可以加一句：网页类的东西（文档、看板、内容库）走的是 web 那一格，目前 connector 覆盖最差。同事「从公众号里摘文字发给客户」，卡的就是这一格。

你自嘲「一知半解地出去误人子弟了」。挺准：你对这套东西的感觉是对的，但还没到能讲给别人的程度。他说「需要先建立心智模型才能理解」。

快脑，慢脑，和身体

人这一侧

从这一章起，主角换成人。先学的第二个就在这里：一个人可以很会「看出模式」，却不太会「一步步推」。这件事决定你怎么读同事，也决定你怎么读自己。

系统一，系统二

一句话系统一是快的、自动的「一眼看出来」；系统二是慢的、费劲的「一步步推」。抽象能力属于系统一，不属于系统二。

展开看到一张脸，你一瞬间就知道对方在生气，这是系统一。心算 17 × 24，你得停下来一步步算，这是系统二。这对名字是两位心理学家 2000 年提的，卡尼曼 2011 年的《思考，快与慢》让它出了圈。卡尼曼是心理学家，拿的却是诺贝尔经济学奖，所以 Ronin 说这是「经济学从认知科学借走的术语」。

他加的那一层才是重点他说自己以前以为抽象能力强的人，逻辑也强。后来发现错了：抽象的起点是模式识别，那是系统一。所以一个人可以一眼看出隐喻、看出小概率事件之间的关联，同时逻辑推理只是普通水平。你当场确认了，说的就是你。

它的坑错误的抽象，加上事后找理由。他的比喻是「没有一楼，挖了一个地下室」。例子是「因为某件事，就宣判某个人社交死亡」。你说前几年做得出这种事，现在觉得傻。

机器那一侧他文档里说，GPT-4 只有系统一；o1、R1 接上了系统二，却出了新毛病：长长的推理里，第三步把「有可能」当成「就是」。系统一和系统二不是两个模型，是同一个旋钮的两档，差在「转几圈」。

马上能用的练习你对同事的行为冒出一个解读时（系统一给的），先给它贴个标签：「假设」。然后逼自己找一条相反的证据。找不到，再当真。这一步就是手动接上系统二。可以并进你 Gallup 计划里的「周二一问一认」。

卡尼曼那本确实难读，不是翻译的锅。只想拿走概念，读第一部分（系统一二）和第三部分（过度自信）就够。

一句话杏仁核是大脑的烟雾报警器，负责「快跑」；前额叶是总指挥，负责计划和刹车。压力一大，报警器会把总指挥压下去。

知识不在任何一个人那里

一句话哈耶克说，有用的知识散在每个人手里，没有哪个中心能收齐；价格，就是把这些散的知识汇总起来的信号。

展开番茄减产了，没人挨家挨户通知你，但菜市场的番茄涨价了，大家自然就少买一点。几百万人「当时当地」的小知识，被压缩成了一个数字。这是哈耶克 1945 年《知识在社会中的运用》的意思。Ronin 说他「比卡尼曼更抽象」。

它为什么出现Ronin 说「我们并不拥有知识，知识属于上帝」，你说想翻阅他的大脑。哈耶克的版本是：知识不在任何一个人那里，在人和人之间。这也是他那句「平台撮合的是人，AI 生不出这个」的底子。

注意力残留：一只脚还卡在门里

一句话每次换一件事，上一件事都会在脑子里留下一点残留，占着下一件事的位置。反复看消息，就是在不停制造残留。

展开像从一个房间走到另一个房间，一只脚还卡在门里。研究者 Sophie Leroy 2009 年给它起名叫「注意力残留」，没做完的事残留更重。Ronin 的做法是工作时不看手机、不反复确认消息，因为「反复确认会让大脑持续保持被触达的状态」，而「碎片化信息会让自己觉得这一天没什么进展」。这两句都能追到司马贺那句「信息的丰富造成注意力的贫乏」。

跟你的关系你已经在订会议室专注干活了。他补的一步是：把电脑上的微信也关掉。你回的是「再聊几句再关」。

睡 5 到 6 个周期

一句话一个睡眠周期大约 90 分钟。成人一晚睡 5 到 6 个周期，也就是 7.5 到 9 小时。

展开这是他那句「你应该现在入睡，然后睡 5-6 个周期（7.5-9）」。90 分钟只是平均，每个人在 70 到 120 分钟之间浮动，按周期定闹钟只是个粗略工具。白天补觉（你的全季钟点房方案）也不冲突：睡 20 分钟，或者睡满一个周期；中间长度最容易在深睡里被叫醒。

他又补过两句。「累的时候就好好休息，控制慢性压力」：这句很扎实，长期压力的累积会伤身体，也伤前额叶，接上一张卡。「建议早上运动」：证据没那么硬，2019 年一篇综述发现晚上运动一般不影响睡眠，只有睡前一小时内的剧烈运动会让入睡变难。

跟你的关系你晚上八点多运动、十一点睡，问题不大。早上运动真正的好处是：不会被加班挤掉。

  • 概念图和思维导图不一样：思维导图是从中心长出来的一棵树；概念图是一张网，每条线上要写关系（导致、属于、取决于），读出来是一句完整的话。
  • 和神经网络的关系：语言学家 Firth 说过「看一个词的伙伴，就知道它的意思」。2013 年的 word2vec 把每个词变成空间里的一个点，意思全靠它和别的点的相对位置。最有名的例子：国王 − 男人 + 女人 ≈ 女王。
  • 他那句「像程序的 build」：写一段文字，是把网状的想法压成一条线；读的人要把线还原成网。

跟你的关系「开发就是人力」正在被 AI 改写，这也是你说的「AI 后非码农的产品创意有机会实现了」。但本章开头那条结论不变：做出来越来越便宜，有人用才是难的。

跟你的关系你是公司「内部有余力聘请的人」，不是外人。这是优势：你有授权，有上下文。给自己的定位可以写成「企业内部的 AI 转型负责人」，比「FDE」准，也更好讲。「AIO」具体指什么他没说，放进最后一章的问题里。

SICP：用一层层的墙管住复杂

一句话MIT 1985 年的编程入门书。它教的不是哪门语言，是怎么用「抽象」管住复杂。

展开核心是「抽象屏障」：每一层只露出接口，藏住怎么做的。像公司里的交接，上游只交一份文件，下游只读那份文件，不需要知道上游开了几次会。书里最有名的一句：「程序首先是写给人读的，其次才是给机器执行的。」

他那份 AI 编程流程图「基于 SICP 和 Anthropic 的 SDLC」：从需求、规格、计划、代码到验收，每层产出一份东西，下一层只读这份东西。他说「普通人没有古法手搓编程的话，缺乏对应的心智模式」，指的就是：拆分、分层、守住不变的规矩。

你嫌它把简单事说复杂。他的回答是「和你想控制的规模有关系」：街边包子店，一个本子记流水就够；要同时管 10 台、100 台云主机，就复杂了。你说：「那不就是我现在做的吗。」所以这套东西你迟早要用。

最省力的入门不读书。看 1986 年 MIT 的 SICP 视频课第一讲（约一小时），或者只读书的 1.1 节和 2.1 节。

有 1000 个人需要你，你就成功了

一句话他问你怎么定义成功，你列了一长串条件。他说：「有 1000 个人需要你，你就成功了。」

合起来是三个条件：有人需要、非你不可、能分发出去。Kevin Kelly 2008 年有篇《一千个真粉丝》：一个创作者有 1000 个愿意每年为你花 100 美元的人，就能靠作品生活。他的版本把「粉丝」换成了「需要你的人」，又加了后两个条件。

他还发过一条讲彼得·蒂尔「三个时间尺度」的视频，说「觉得你需要」：短期看开不开心、学没学到，中期看简历，长期看重不重要。你回：「我现在工作的短期和中期价值是有的，长期价值是偏弱的。」

跟你的关系拿三个条件检查手上的事：有没有一群具体的人需要（DLG 同事、培训学员、玩你游戏的人）？他们是不是非你不可？你的东西能不能不靠你本人就被分发出去（课程、工具、文章）？你说的「长期价值偏弱」，大概就是第三条还没有。

声音这一块，你是老师

一句话他问你音乐、音效、配音有没有好用的服务，你给他讲了影视声音是怎么分工的。这一条，是你教他。

展开你讲：AI 之前，一部片子的声音要好几个部门。配音进棚做 ADR（演员后期重录对白）；音效分环境音、合成的特殊音效、拟声；音乐又是另一个领域。拟声英文叫 Foley，就是人碰到东西时的声音：翻书、笔尖划纸、衣服摩擦。这个名字来自 1920 年代末在环球影业做现场拟声的 Jack Foley。你还说音效「是一个不太被重视的部门」，要是能把这些细分全组合起来，「确实可以做出一个史无前例的工具」。

「中之人」：不出镜，也能做自媒体

跟你的关系你最怕的不是被看见，是被冤枉。所以真要做，先做文字和声音，评论区怎么处理提前想好（不回、只回事实、或者交给助手），这比先克服镜头重要。

房间里最高的人

一句话你说聊 AI 时身边基本只有你在输出，你需要输入。他说：「如果你是房间里最高的人，说明你来错了地方。」又补了一句：要找一个相对的位置，不能太高也不能太低。

谁受益，谁受损

一句话你讲了和一位同事的冲突。他没评对错，只让你问两个问题：「整个事情，谁受益，谁受损？」以及「谁授权的？」

  • 「因为你的出现本身，而非你的行为影响了他。」「你的存在属性不是由你决定，而是由 leader 决定。」

「谁受益」是一句古罗马法谚 cui bono：查案先看谁从中得利。

跟你的关系他给的是一套把情绪换成结构的问法。下次再遇到，先写三行：这件事的授权人是谁；我的出现改变了谁的处境；谁从现在的局面里得利。写完再决定是友善还是正面冲突。你自己已经说过「可能老板只是要我的出现来敲打他」，这就是第三行。

第二天晚上你说公司「明显风光不再了」，打算写简历。他问：「关键是你想要什么？」你说养活自己、尽可能多赚点。他引你自己的话回了一句：「你的表达是自己能够被人尽其才。」最后他说：「因为你确实被气到了。」「需要抱抱被气到的自己，让自己不生气。」他没给建议，给的是两件事：先弄清目的，先照顾好此刻的情绪。

父母的「上下文」固化了

一句话国庆回家你和家里吵了几次。他的解释是：现在强大的那个人是你；而父母，像大模型一样，会留在自己的那个年代。

展开你说早上和爸爸吵架，他说：「因为，现在强大的人是你。」「你还没有习惯这具强大身体里的力量如何与家庭成员之间配合。」「当然，他们也很不习惯。」后来你讲到一位长辈替你弟弟讲「吃苦论」，喝醉了还打电话催婚，爸妈默许，你说自己「在这方面有点应激」。他说：「看来你想要分家了。」「其实父母也是小朋友。」「只是每个人的 context layer 发生不同程度的固化。」「人其实和大模型的型号是一样的，会留在过去。」

现成的说法家庭治疗里有个词叫「自我分化」：和原生家庭保持感情上的连接，同时不被家里的情绪和规矩带着走。分化得好的人能做到「不同意，但不翻脸」。他说的「分家」不是搬出去，是这个意思。

跟你的关系大模型的比喻很好用。模型有训练截止日期，你不会因为它不知道最新消息而生气，只会补上下文。对父母也一样：催他们进步，是往一个旧模型里硬塞新知识，效果有限。更省力的是，先决定哪些事你自己拍板，不需要他们同意。

兴趣变成钱，兴趣就没了

一句话你说他研究这么前沿，回报还没跟上。他连着回了四句，合起来是一套关于回报的看法。

  • 「居于木雁之间，应有龙蛇之变。」出自《庄子·山木》：山里的大树因为没用活下来，主人家的鹅因为不会叫被杀了。弟子问该怎么办，庄子先说「处在有用和没用之间」，又自己否定了一半，说更好的是像龙和蛇，该显就显，该藏就藏。
  • 「找到一个长长的雪坡滚雪球会更好玩一些。」巴菲特：人生像滚雪球，要找很湿的雪和很长的坡。说的是复利。
  • 「把自己的兴趣变成钱，兴趣很快就没了。」心理学叫「过度理由效应」：本来爱画画的小孩，被告知画了有奖之后，自由时间里反而画得少了。事先许诺、和表现挂钩的奖励最伤兴趣；事后意外的奖励和夸奖不会。
  • 「金融即融金。」字面倒过来读：让钱自己流动、自己生钱，和滚雪球是一回事。这是一种解读

后来他说你是「一个等待戈多的人」，又说：「如果你能明确地知道自己的天命，你就有足够的理由燃烧自己。」你说天命是辅佐，他回：「还没有起风。」不知道自己要什么时，人会一直等；知道了，就值得全力投入；什么时候投入，要等风。和「龙蛇之变」是同一个判断。

跟你的关系你说过自己「不能允许任何一件交到我手里的事情因为我的能力而失败」。这句定的是别人交来的事的标准。他那几句问的是另一件事：你自己选的事，是什么。

清洁是熵减，很累

一句话一个下雨天，他说「清洁是熵减，很累」，然后讲了一串关于复杂和衰老的话。

你：今天外面雨绵绵，晚饭可以外卖（请好好吃饭
他：清洁是熵减，很累。今天已经吃过了，晚上就不吃了，正好禁食 16 小时
他：人生就是负担越来越多，复杂性越来越高

熵减先说人话屋子不收拾会越来越乱，这是世界的默认方向，叫熵增。把它收拾整齐，要花力气，叫熵减。

为什么收进来这不是知识点，是状态。和上一张卡是同一件事的两面：占有和连接都要付代价，代价是复杂，复杂让人老。你一边说「不能允许交到我手里的事失败」，一边说「很久没有想要占有一个人的冲劲了」，这两句放在一起，比任何一个概念都值得想一想。

n+1 层：能看见自己的那一层

一句话他和钱鹏飞从「什么是值得过的生活」聊到宗教、哲学和 AI：各种安身立命的经典，都在人身上造一个「n+1 层」，也就是能看见自己的那一层。

展开他说：「这个觉察就是观自在菩萨的观自在，就是古希腊神庙上的认识你自己，就是王阳明的知行合一，也是道家的内观，科学家的内省。」「在研究者来看就是元认知，佛教称之为般若。」（小更正：「认识你自己」刻在德尔斐的阿波罗神庙，不是帕特农神庙。般若的意思是智慧。）

钱鹏飞说：「佛提供了闭环，哲学没有闭环，提供了一个知性循环路径，后者引领科学改变世界。」他接：「他们的 loop engineering 选择了不同的拓扑。」说人话：都是循环，形状不一样。一个绕回原点，一个一直往外开口。

还有一句接得上司马贺：「旧的机制选择了最便宜最可行的方案，不追求最优，追求当前最可用。」

你的回应你讲了大学朋友怎么把你从低谷里拽回来。他说「你在拟态」「会比较耗蓝」：拟态是一种生物模仿另一种的样子，蓝条是游戏里的法力值。意思是你在学那位朋友的乐观画风，但那不是你的出厂设置，维持起来费劲。你回：「我证明个毛线，我本来就好得很。」后来他说：「你只是在表达。」

跟你的关系「n+1 层」就是你这几个月在练的东西：写复盘，让 Claude 分析你们的对话，做这份清单，都是在给自己加一层能看见自己的眼睛。
